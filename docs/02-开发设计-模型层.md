## 1. 模型后端接口

```rust
/// 模型后端统一接口（定义在 mindvoid-core）
pub trait ModelBackend: Send + Sync {
    /// 推理：给定特征上下文，返回 Top-K 候选
    fn predict(&self, features: &FeatureVec) -> Vec<Prediction>;

    /// 增量训练：单条样本即时更新
    fn train_incremental(&mut self, sample: &TrainSample);

    /// 批量训练：多条样本全量更新
    fn train_batch(&mut self, samples: &[TrainSample]);

    /// 序列化到文件
    fn save(&self, path: &Path) -> Result<()>;

    /// 从文件加载
    fn load(path: &Path) -> Result<Self> where Self: Sized;

    /// 模型统计信息
    fn stats(&self) -> ModelStats;
}

pub struct Prediction {
    pub text: String,       // 候选词/短语
    pub confidence: f32,    // 置信度 [0, 1]
}

/// 训练样本
pub struct TrainSample {
    pub keystroke_seq: Vec<char>,   // 按键字符序列（原始按键）
    pub context: String,            // 已确认的前上文
    pub output: String,             // 用户最终落地的文本
    pub app_context: String,        // 应用场景
    pub confidence: Confidence,
}

pub enum Confidence { High, Low, ImplicitNegative }
```

### FeatureVec 扩展

`FeatureVec` 需包含三类输入信号：

```rust
pub struct FeatureVec {
    pub keystroke_chars: Vec<char>,  // 当前按键序列（用户正在敲的，未确认）
    pub context_chars: Vec<char>,    // 前上文（已确认进入输入框的文本）
    pub app_context: String,         // 应用场景标签
    pub time_bucket: u8,             // 时间段编码（0=凌晨, 1=上午, 2=下午, 3=晚上）
}
```

## 2. 深度学习预测模型（研究课题）

> ⚠️ **重要：预测模型是本项目的核心学习研究课题。**
> 以下描述的方案是当前的设计方向和参考实现思路，**不作为最终定案**。
> 具体实现需在实验中逐步确定和优化。

### 2.1 问题定义

```
输入信号:

  1. 按键序列（用户正在敲的拼音/英文，未确认）
  2. 前上文（已确认进入输入框的文本，动态累积）
  3. 环境特征（应用、时间等）

输出:
  预测用户最终要输入的文本内容（中英文混合）

示例:
  按键="jwcsm"  前上文=""     → "今晚吃什么"     (拼音缩写展开)
  按键="jinwan" 前上文=""     → "今晚"            (拼音片段)
  按键="ily"    前上文=""     → "i love you"      (英文缩写)
  按键="g"      前上文="我想" → "去、过、个"      (逐字预测)
  按键="t"      前上文=""     → "the, today, 他"  (中英混出)
```

**核心设计原则：**不区分中英文模式，模型根据输入信号自动判断输出中文还是英文。三个输入信号平行进入模型，共同决定输出。

### 2.2 模型架构

采用 **Transformer Decoder**（类似小型 GPT）：

```
按键序列  ──→ [Token Embedding] ──┐
前上文    ──→ [Token Embedding] ──┤ 拼接 → [Position Embedding]
环境特征  ──→ [Token Embedding] ──┘
                                        ↓
                               [Transformer Decoder × 2 层]
                                ├─ Masked Multi-Head Attention (4 head)
                                ├─ Feed-Forward (Dense 256 → ReLU → Dense 64)
                                └─ 残差连接 + LayerNorm
                                        ↓
                                [Dense + Softmax over vocab ~6500]
                                        ↓
                                Top-K 候选文本（支持短语级别）
```

**关键参数：**

| 参数 | 参考值 | 说明 |
|------|--------|------|
| 词表大小 | ~6500 | SentencePiece 自动构建的混合词表 |
| Embedding 维 | 64 | 小模型，CPU 推理 |
| Decoder 层数 | 2 | 层数越多数据需求越大 |
| Attention Head | 4 | 标准配置 |
| 最大序列长度 | 64 tokens | 按键+前上文+环境标记 |
| 输出 Top-K | 5 | 展示候选数量 |

### 2.3 词表方案：SentencePiece

词表使用 **SentencePiece（Unigram 模式）** 自动生成，无需手写。

```
pip install sentencepiece

训练命令:
  spm.SentencePieceTrainer.train(
      input='中英混合语料.txt',
      model_prefix='mindvoid_vocab',
      vocab_size=6500,
      model_type='unigram',
      split_by_whitespace=False,   # 中文不分空格
      character_coverage=0.9995,
      split_digits=True,           # 数字单独
  )

产出:
  mindvoid_vocab.model   ← 词表文件，加载到推理
  mindvoid_vocab.vocab   ← 可查看的词表文本

词表内容（自动学习）:
  汉字:         的、一、是、在、我、不、了、有、这...
  中文双字短语:  今天、可以、我们、什么、没有...
  中文多字短语:  今晚吃什么、我喜欢、没问题...
  英文词:       the, to, today, Apple, love, good...
  英文字母:     a~z
  标点数字:     ,.!?0-9
```

**SentencePiece 的特性：**
- 语言无关：输入中英混合语料，产出中英混合词表
- 自动学短语：高频共现的字会合并为一个 token
- 覆盖性：6500 词表覆盖日常 99% 输入场景

**支持的输入模式示例：**

```
"jwcsm"        → 词表中有 "今晚吃什么" 短语→ 一步输出
"jinwanc"      → 词表中有 "jin"+"wan"+"c" → 拼音片段组合
"i love you"   → 词表中整句 → 直接输出
"ilove"        → 部分匹配 → 生成完整短语
"我想去Apple"  → 中英混合 → 正常输出
```

### 2.4 模型输入信号编码

三类信号在进入模型前编码为统一的 token 序列：

```
编码示例:

按键序列 "jin":
  [j] [i] [n]    ← 每个按键字符一个 token

前上文 "我想":
  [我] [想]       ← 每个汉字一个 token

环境特征:
  [微信] [晚上]   ← 类别编码为特殊 token

最终输入:
  [j] [i] [n] [SEP] [我] [想] [SEP] [微信] [晚上]
   ↑ 按键序列    ↑ 前上文        ↑ 环境标记

  SEP 是特殊分隔 token，让模型识别三段的边界。
```

**为什么不用编码器分路处理再拼接？** 统一序列 + Position Embedding 已经可以区分位置关系。小模型下统一编码更简单高效。

### 2.5 推理流程

```rust
impl ModelBackend for TransformerModel {
    fn predict(&self, features: &FeatureVec) -> Vec<Prediction> {
        // 1. 编码三类信号
        let tokens = self.tokenizer.encode(
            &features.keystroke_chars,   // 按键序列
            &features.context_chars,      // 前上文
            &features.app_context,        // 环境
        );

        // 2. Transformer forward
        let logits = self.transformer.forward(&tokens);

        // 3. Softmax → Top-K 候选
        self.top_k_candidates(&logits, 5)
    }
}
```

**自回归生成过程（如需生成短语）：**

```
输入: [j][w][c][s][m][SEP][SEP][微信][晚上]

Step 1: 模型前向 → 输出 token id=803 ("今晚吃什么")
        词表中 "今晚吃什么" 是单 token → 一步输出
        概率 0.7

Step 2: 同时输出其他候选项:
        token id=409 ("今晚")
        token id=12  ("今")
        token id=803 ("今晚吃什么")

最终输出:
  1. "今晚吃什么" (7.0)
  2. "今晚"       (4.5)
  3. "今晚吃"     (2.1)
  4. "今"         (1.8)
  5. "今晚吃什"   (1.5)
```

### 2.6 短语展开机制

"jwcsm → 今晚吃什么" 的工作原理：

| 机制 | 说明 |
|------|------|
| 词表包含完整短语 | SentencePiece 从数据中学到"今晚吃什么"作为独立 token |
| 训练样本 | 用户的真实输入记录：`jwcsm → 今晚吃什么` |
| 模型学习模式 | Transformer 的 Attention 学到"jwcsm"模式和对应输出 |
| 冷启动 | 无用户数据时，预训练的短语覆盖通用场景 |

**短语提取：** 用户数据中高频共现的 n-gram 自动成为 SentencePiece 词表中的短语 token。完全自动化，无需手动维护。

## 3. 兜底方案（传统 N-Gram）

在深度学习模型不可用或冷启动阶段，使用传统 N-Gram 提供基础预测能力。

### 3.1 参考方案：字级别 N-Gram

| 参数 | 参考设定 | 说明 |
|------|---------|------|
| N | 4（3 字上下文 → 1 字预测） | 可按需调整 |
| 数据结构 | `BTreeMap<[char;3], BTreeMap<char,u32>>` | 计数统计 |
| 预测 | 基于历史计数 Top-K | 纯统计 |
| 更新 | 每次用户选择后即时调整计数 | 在线学习 |
| 冷启动 | 零样本 + 高频字 fallback | 首日可用 |

### 3.2 序列化

```
文件格式: (magic + version + 数据段 + CRC32 校验)
 
文件头:
  magic:    [u8;4] = b"NG4M"
  version:  u32 = 1
  n:        u32 = 4

数据段:
  prefix:   [char;3] → { next_char: count } 映射表
  checksum: u32   (CRC32 of data section)
```

原子写入：`write(tmp) → fsync → rename`。

## 4. 训练流水线

### 4.1 数据收集

训练数据由系统自动积累：

```sql
CREATE TABLE training_samples (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    keystrokes  TEXT NOT NULL,       -- 按键序列 "jwcsm"
    context     TEXT,                -- 前上文 "我想"
    output      TEXT NOT NULL,       -- 落地文本 "今晚吃什么"
    app_name    TEXT,                -- "微信"
    time_bucket INTEGER,            -- 0-3
    confidence  TEXT,                -- 'high' | 'low'
    created_at  TEXT DEFAULT (datetime('now'))
);

PRAGMA journal_mode=WAL;
```

### 4.2 在线训练

```rust
pub struct TrainingPipeline {
    hot_buffer: Arc<Mutex<Vec<TrainSample>>>,
    batch_size: usize,
    model: Arc<ArcSwap<dyn ModelBackend>>,  // 可切换模型实现
}

impl TrainingPipeline {
    /// 事件线程调用：追加样本（非阻塞，仅 push）
    pub fn push_sample(&self, sample: TrainSample) {
        self.hot_buffer.lock().unwrap().push(sample);
    }

    /// 训练线程调用：批量取走并训练
    pub fn drain_and_train(&self) {
        let mut buf = self.hot_buffer.lock().unwrap();
        if buf.len() >= self.batch_size {
            let batch: Vec<_> = buf.drain(..).collect();
            drop(buf);
            self.train_batch(batch);
        }
    }

    fn train_batch(&self, samples: Vec<TrainSample>) {
        let current = self.model.load();
        let mut new_model = (*current).clone();
        for sample in &samples {
            new_model.train_incremental(sample);
        }
        self.model.store(Arc::new(new_model));
    }
}
```

**训练策略：**

| 策略 | 触发条件 | 耗时 | 备注 |
|------|---------|------|------|
| 即时微调 | 每 50 条新样本 | ~100ms 后台 | N-Gram 快速更新 |
| 微调训练 | 每 500 条新样本 | ~1s 后台 | Transformer 微调 |
| 全量重训 | 手动 / 每日 | ~30s-5min | 重新建 SentencePiece 词表 |
| 冷启动 | 首次运行 | 立即 | N-Gram 空表 + 高频字 fallback |
