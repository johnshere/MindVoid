## 1. Crate 划分与模块边界

```
mindvoid/
├── mindvoid-core/        # 零平台依赖：所有 trait 定义 + 核心数据结构
├── mindvoid-model/       # 统计模型引擎（见 02-开发设计-模型层.md）
├── mindvoid-adapter/     # 平台适配层，按 feature flag 编译
│   ├── win/              #   Windows: WH_KEYBOARD_LL + UIA + Win32 UI
│   ├── macos/            #   macOS: CGEventTap + AXObserver + Metal
│   └── linux/            #   Linux: XRecord + AT-SPI + X11/Wayland
├── mindvoid-ui/          # Overlay 浮窗渲染（见 02-开发设计-用户界面层.md）
├── mindvoid-app/         # 主进程入口，组装各模块，管理生命周期
└── mindvoid-cli/         # CLI 工具：模型快照管理、诊断导出、测试回放
```

**依赖方向（单向，严禁反向）：**

```
mindvoid-app ──→ mindvoid-core
             ├──→ mindvoid-model ──→ mindvoid-core
             ├──→ mindvoid-adapter ──→ mindvoid-core
             └──→ mindvoid-ui ──→ mindvoid-core
```

`mindvoid-core` 零外部依赖（标准库除外）。

## 3. 线程模型

### 3.1 线程清单

| 线程 | 职责 | 通信方式 | 优先级 |
|------|------|---------|--------|
| **钩子回调线程** | WH_KEYBOARD_LL 回调，记录原始事件 | **无锁 SPSC queue** push 端 | 最高（系统 <1ms 限制） |
| **事件处理线程** | 消费原始事件，字符解码，驱动管线 | SPSC pop → 内部 channel 分发 | 中 |
| **推理线程** | 执行 N-Gram predict() | `tokio::sync::oneshot` 请求-响应 | 低（可被取消） |
| **训练线程** | 异步增量训练，样本持久化 | `Arc<Mutex<VecDeque<Sample>>>` | 最低（后台） |
| **UI 主线程** | 消息循环 + 浮窗渲染 | Win32 消息队列 | 中 |

### 3.2 钩子 → 事件处理：SPSC 无锁队列

```
┌─ 钩子回调(系统线程) ──┐        ┌─ 事件处理(自有线程) ──┐
│                       │        │                        │
│ 回调内只做三件事：      │  push  │  1. pop 原始事件        │
│ 1.读取性能计数器        │ ────→ │  2.字符解码(VkKeyScan)  │
│ 2.push 到无锁队列       │        │  3.送入敏感过滤         │
│ 3.return (<100μs)      │        │  4.分流入判定器         │
└───────────────────────┘        └────────────────────────┘
```

使用 `crossbeam::channel` 或自建 `AtomicPtr` 链表队列。队列容量设 1024（约 2 秒缓冲，远超需要）。

### 3.3 推理取消机制

```rust
use tokio_util::sync::CancellationToken;

struct InferTask {
    cancel_token: CancellationToken,
    request: InferRequest,
}

// 用户继续打字 → 取消上一轮推理
fn on_new_keystroke() {
    if let Some(prev) = current_infer_task.take() {
        prev.cancel_token.cancel();
    }
    // 创建新 token 和新任务
}

// 推理线程检测取消
async fn infer_loop(token: CancellationToken, request: InferRequest) -> Option<Vec<Prediction>> {
    let model = MODEL.read();
    for step in compute_steps {
        if token.is_cancelled() { return None; }
        // ... 计算步骤
    }
    Some(result)
}
```

### 3.4 共享状态保护策略

| 数据 | 保护机制 | 读写模式 | 理由 |
|------|---------|---------|------|
| TargetPool | `Arc<RwLock<LruCache>>` | 判定器写 ↔ 推理读 | 写少读多，RwLock 足够 |
| 环形缓冲区（每目标） | 单写者(判定器) + `Arc<AtomicPtr<[u8]>>` 快照 | 判定器写 → 分段器读 | 无锁读取 |
| N-Gram Trie 计数 | `Arc<ArcSwap<Trie>>` | 训练线程写 → 推理线程读 | 原子替换，读零开销 |
| 训练样本队列 | `Arc<Mutex<VecDeque<Sample>>>` | 事件线程写 → 训练线程批量取 | 简单，操作不频繁 |

## 4. 进程架构

Phase 1 采用**单进程多线程**方案：

```
┌──────────────────────────────────────────────┐
│               mindvoid-app.exe               │
│                                              │
│  ┌──────────┐  ┌──────────┐  ┌────────────┐ │
│  │ 钩子线程   │  │ 事件线程   │  │ UI 主线程    │ │
│  │(独立消息   │→│(管线驱动)  │  │(Win32消息    │ │
│  │ 循环)     │  │          │  │ 循环+浮窗)   │ │
│  └──────────┘  └──────────┘  └────────────┘ │
│                      │              ↑         │
│                      ↓              │         │
│                ┌──────────┐  ┌────────────┐  │
│                │ 推理线程   │  │ 浮窗 HWND    │  │
│                └──────────┘  └────────────┘  │
│                      │                        │
│                ┌──────────┐                   │
│                │ 训练线程   │                   │
│                └──────────┘                   │
└──────────────────────────────────────────────┘
```

**要点：**
- WH_KEYBOARD_LL 钩子回调在**钩子线程自己的消息循环**中，不与 UI 消息循环冲突
- UI 线程负责 Win32 消息循环（`GetMessage` → `DispatchMessage`）+ 浮窗渲染
- 未来如果延迟不满足，可拆为双进程（Core 后台服务 + UI 前台），用共享内存传递候选

## 5. 生命周期管理

### 5.1 启动顺序

```
 1. parse_config()           ──失败→ 使用默认配置
 2. init_logging(tracing)    ──失败→ stderr 兜底
 3. check_accessibility()    ──失败→ 降级模式(无 Branch 2)
 4. init_ui_adapter(UIA)     ──失败→ ERROR，部分功能不可用
 5. init_target_pool()       ──依赖步骤 4
 6. init_ngram_model()       ──失败→ 空模型冷启动
 7. init_filter() + init_judger() + init_segmenter()  ──纯计算，不会失败
 8. install_keyboard_hook()  ──失败→ FATAL 退出
 9. start_infer_thread() + start_train_thread()  ──失败→ 无预测，继续运行
10. create_overlay_window() + enter_message_loop()  ──UI就绪
```

### 5.2 关闭顺序

```
 1. set_shutdown_flag()         ──通知所有线程准备退出
 2. uninstall_keyboard_hook()   ──务必在消息循环退出前调用
 3. cancel_pending_infer()      ──丢弃排队推理任务
 4. flush_train_samples()       ──内存样本写入SQLite
 5. serialize_ngram_trie()      ──原子写入: write(tmp) → rename(target)
 6. cleanup_com() + destroy_window()
```

### 5.3 崩溃恢复

| 组件 | 策略 | 崩溃损失 |
|------|------|---------|
| N-Gram Trie | `write(tmp) → rename(target)` 原子写入 | 最多丢失 1 batch |
| 环形缓冲区 | 不持久化 | 最多 512 字符上下文 |
| 训练样本 | 累积 50 条后批量写 SQLite (WAL) | 最多 49 条 |
| 配置文件 | 只读，用户手动编辑 | 无 |

## 6. 错误处理

### 6.1 错误类型

```rust
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error("辅助功能权限被拒绝")]
    AccessibilityPermissionDenied,

    #[error("键盘钩子权限被拒绝")]
    HookPermissionDenied,

    #[error("UIA 调用失败: {hr}")]
    UiaCallFailed { hr: i32 },

    #[error("键盘钩子安装失败: {code}")]
    HookInstallFailed { code: u32 },

    #[error("模型文件损坏: {path}")]
    ModelCorrupted { path: PathBuf },

    #[error("加载模型失败: {path} — {reason}")]
    ModelLoadFailed { path: PathBuf, reason: String },

    #[error("磁盘空间不足")]
    DiskFull,

    #[error("IO 错误: {0}")]
    IoError(#[from] std::io::Error),

    #[error("{0}")]
    Internal(String),
}

pub type Result<T> = std::result::Result<T, Error>;
```

### 6.2 降级矩阵

| 故障 | 降级行为 | 用户感知 |
|------|---------|---------|
| 辅助功能权限被拒 | 关闭 Branch 2（环境采集），判定器仅用 Branch 1 | 预测准确率下降，但正常打字不受影响 |
| UIA 调用超时 | 跳过本次环境采集，用上次缓存值 | 预测可能短暂不准 |
| 键盘钩子被安全软件拦截 | **FATAL**：弹窗引导用户加白名单 → 退出 | 无法运行 |
| 模型文件损坏 | 删除损坏文件，冷启动空模型 | 历史训练数据丢失 |
| 磁盘空间不足 | 停止训练写入，仅内存操作 | 重启后丢失本次训练 |
| SQLite 写冲突 | WAL 模式 + 3 次重试 → 丢弃 | 最多丢一批样本 |

### 7.1 环形缓冲区

```rust
pub struct CharRingBuffer {
    buf: Vec<u8>,           // UTF-8 字节，512 字符 ≈ 2KB
    cursor_byte_pos: usize, // 光标所在的字节偏移（<CURSOR> 标记）
    char_len: usize,        // 当前字符数
    max_chars: usize,       // 512
}

impl CharRingBuffer {
    /// 尾部追加字符
    pub fn append(&mut self, chars: &str) {
        // 确保 buf 有足够空间，必要时从头部丢弃
    }

    /// 无锁快照：返回 buf 当前内容的不可变引用
    /// 注意：仅在单写者场景下安全——判定器暂停写入后调用方读取
    pub fn snapshot(&self) -> &str {
        std::str::from_utf8(&self.buf).unwrap_or("")
    }

    /// 光标移动到 pos，丢弃 pos 之后的字符
    pub fn trim_to_cursor(&mut self, char_pos: usize) {
        // 更新 cursor_byte_pos，截断 buf
    }
}
```

**设计要点：**
- 单写者（判定器）写入，分段器通过 `snapshot()` 读取。判定器写入期间分段器不应该读，由事件线程通过"写完再发信号"保证
- 512 字符上限，超出时从头部丢弃最老的字符
- `cursor_byte_pos` 记录光标在缓冲区中的位置，解决 §9.2 的光标语义断裂问题

### 7.2 TargetPool

```rust
use lru::LruCache;
use std::sync::RwLock;

pub struct TargetPool {
    targets: RwLock<LruCache<TargetId, TargetContext>>,
}

pub struct TargetContext {
    pub target_id: TargetId,
    pub ring_buffer: CharRingBuffer,
    pub cursor_prefix: String,  // 最近一次环境采集的光标前文本
    pub cursor_suffix: String,
    pub last_env_text: String,  // 上一轮环境文本快照（判定器的 prev_env）
    pub process_name: String,
    pub window_title: String,
    pub cached_predictions: Vec<Prediction>,
    pub last_active: Instant,
}
```

**LRU 淘汰：** 池上限 16，超限时淘汰 `last_active` 最小的目标。淘汰前不清空旧目标缓冲区（后续切回时可恢复）。

**隐私策略：** 切换到黑名单应用时强制清空当前目标缓冲区，避免残留。

### 7.3 判定器实现

```rust
impl Judger {
    pub fn judge(&self, b1: &[char], b2: Option<&str>, prev_env: Option<&str>) -> BufferOp {
        match (b2, prev_env) {
            (Some(current), Some(prev)) if current.len() > prev.len() => {
                let added = &current[prev.len()..];
                if self.is_continuous_chars(b1, added) {
                    BufferOp::Append { chars: added.to_string() }
                } else {
                    // IME 选词 / 粘贴：增量不连续，整体替换
                    BufferOp::ReplaceAll { text: current.to_string() }
                }
            }
            (Some(current), Some(prev)) if current.len() < prev.len() => {
                let removed = prev.len() - current.len();
                BufferOp::TrimTail { count: removed }
            }
            (None, _) | (_, None) => {
                // 降级模式：无环境采集数据，信任分支 1
                let s: String = b1.iter().collect();
                BufferOp::Append { chars: s }
            }
            _ => BufferOp::Append { chars: String::new() },
        }
    }

    fn is_continuous_chars(&self, keys: &[char], text: &str) -> bool {
        // 键盘增量字符是否与环境文本增量一致
        // 考虑：直接输入(ascii) vs IME 中间态(拼音字母序列)
        let key_str: String = keys.iter().collect();
        key_str == text
    }
}
```

### 8.2 热加载

使用 `notify` crate 监听 config.toml 变化：

```rust
use notify::{Watcher, RecursiveMode, watcher};

// 独立线程处理

        }
    }

```

热加载规则：部分配置需重启组件（`ring_buffer_chars`），部分实时生效（`debounce_ms`、`filter.*`）。

```
        │ 集成   │  组件间交互：判定器+缓冲区 / 分段器+特征提取
        ├────────┤
        │  单元   │  mock trait：过滤正则 / N-Gram 计数 / 分段规则
        └────────┘
```
